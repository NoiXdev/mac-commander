# Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** File ▸ New Tab (⌘T), "Open in New Tab" for folders, and ⌘-double-click, using macOS window tabs.

**Architecture:** `OpenRequestRouter` learns to open a browser window as a tab of an anchor window (the frontmost browser window), with or without an `OpenRequest`. Core decides which list items count as a folder that opens in a tab. The app wires the menu item, context menus and ⌘-double-click to the router.

**Tech Stack:** Swift 6, SwiftUI `WindowGroup` + AppKit `NSWindow` tabbing, Swift Testing, `L10n` string tables.

**Spec:** `docs/superpowers/specs/2026-11-24-tabs-design.md`

## Global Constraints

- macOS window tabs only: each tab is a full browser window in the anchor window's tab group. No own tab bar.
- ⌘T: new tab at Settings ▸ General ▸ "New windows open" (what ⌘N opens), in the frontmost browser window's tab group; with no browser window, a plain new window. Must not depend on the system's "Prefer tabs" setting.
- "Open in New Tab" / ⌘-double-click: only for folders the list navigates into on double-click — not packages, not archive files, not entries inside an archive. Several folders: one tab each, in selection order, the last one frontmost. ⌘ on files changes nothing.
- Strings in en/de/fr/pl via `L10n` (guards `RawStringGuardTests`, `SourceKeyTests`, `LocalizationCatalogTests`): en "New Tab" / "Open in New Tab"; de "Neuer Tab" / "In neuem Tab öffnen"; fr "Nouvel onglet" / "Ouvrir dans un nouvel onglet"; pl "Nowa karta" / "Otwórz w nowej karcie". Verify each against the system's own strings (e.g. Finder/AppKit `.loctable`s) and use the system wording if it differs; record any change.
- No commits during execution (the user commits on request); Conventional Commits without scope when they are made.

## Review Focus

1. ⌘T with the user's "Prefer tabs: Never" system setting: still a tab, not a separate window.
2. ⌘T while the frontmost window is Settings or an Info window: the tab joins the most recent browser window, or a window opens if there is none — never a tab on the Settings window.
3. "Open in New Tab" on three selected folders: three tabs, in order, last one frontmost, each at its folder; the original tab keeps its folder and selection.
4. ⌘-double-click on an app bundle, an archive file, a file, or a folder inside an archive: behaves exactly like a plain double-click (no tab) — pinned for the classification in Task 1.
5. Relaunch with several tabs open: macOS restores them as tabs, each at its own folder (existing `@SceneStorage`).

### Task 1: Router opens tabs; File ▸ New Tab; folder classification in Core

**Files:**
- Modify: `Sources/MacCommander/App/OpenRequestRouter.swift`, `Sources/MacCommander/App/BrowserCommands.swift`, `Sources/MacCommander/Browser/BrowserWindow.swift` (only if the new window must report its `NSWindow` to the router)
- Modify: `Sources/MacCommanderCore/Browser/BrowserModel.swift`
- Modify: `Sources/MacCommanderCore/Resources/{en,de,fr,pl}.lproj/Localizable.strings`
- Test: `Tests/MacCommanderCoreTests/` (the existing `BrowserModel` test file, or a new `TabFolderTests.swift`)

**Interfaces:**
- Produces: `BrowserModel.folderForNewTab(_ item: FileItem) async -> URL?` — the URL when `open(item)` would navigate into it as a folder outside an archive (a directory, or a non-package symlink to a plain folder); `nil` for packages, archive files, plain files, and while the model shows an archive's contents.
- Produces: `OpenRequestRouter.openNewTab(_ requests: [OpenRequest] = [])` — with no requests, one tab at the "new window" folder; otherwise one tab per request, in order, the last frontmost. Anchor: the frontmost browser window (`browserWindows` / key or main window that is a browser window); without one, plain windows.

- [ ] **Step 1: Write the failing tests** for `folderForNewTab`, using a temporary directory: a folder → its URL; a symlink to a folder → the symlink's URL; a `.app` package directory → nil; a `.zip` file → nil; a plain file → nil; an item while the model lists an archive's contents → nil (use an existing archive test fixture or helper if one exists).
- [ ] **Step 2: Run** `scripts/test.sh --filter '<the suite>'`. Expected: a compile failure.
- [ ] **Step 3: Implement** `folderForNewTab`, sharing the classification with `open(_:)` instead of duplicating it.
- [ ] **Step 4: Implement** `openNewTab` in the router: remember the anchor window, enqueue the requests, open windows through the existing path, and add each new browser `NSWindow` to the anchor's tab group (`addTabbedWindow(_:ordered: .above)` or equivalent, verified in a small AppKit check), independent of `NSWindow.userTabbingPreference`.
- [ ] **Step 5: File ▸ New Tab** (⌘T) directly under the `WindowGroup`'s New Window item, key `menu.file.newTab`. Confirm no other ⌘T exists in the menus (e.g. Format ▸ Show Fonts).
- [ ] **Step 6: Run** `swift build` and `scripts/test.sh`. Expected: a clean build and all tests pass.
